and Gemini manual activity markers), with a new SQLite ledger on port 8768. Runtime source

## Fault-isolation verification

The prior matrix contained eight undeclared timeout-injection events across seven cells.
The corrected batch contains five timeout-injection events, all inside the four declared
`identity-fault-tool-error-001` cells. None occurred outside their declared scope. All four
`identity-fault-tool-latency-001` cells passed. Every provider recorded zero scenario-prohibited
tool executions, identity failures, confirmation failures and audio-gate failures.

Gemini still used the configured server automatic activity detection. The new manual activity
markers were not selected for this benchmark, so this batch does not measure their effect.
All 33 Gemini sessions requested `gemini-3.8-live` and cited the current 3.8 capability report.

## Reproduction and validation

The ledger is `.local/benchmark-5350e4a/development.sqlite`. To reproduce the HTML, run:

```bash
PYTHONPATH=src .venv/bin/python scripts/benchmark_report.py \
  artifacts/provider-matrix/matrix-5350e4a-2026-10-19.json \
  reports/voice-provider-benchmark-5350e4a-2026-10-19.html \
  --database .local/benchmark-5350e4a/development.sqlite \
  --title 'Provider benchmark - revision 5350e4a (ASR-limited)'
.venv/bin/python artifacts/benchmark-5350e4a/annotate_report.py
```

The annotation step adds the assessment limitation, suppresses provider recommendations,
labels raw paired outcomes, and includes provenance. It preserves the recorded statistics.
CI for the measured code revision passed [deterministic checks, lint and audit](https://github.com/Ready2k/Voice_harness/actions/runs/39249079147).
The HTML loaded without JavaScript errors, and the PDF was rendered for visual inspection.
The remaining ASR assessments need replenished transcription credits before a complete,
fairly assessed benchmark can be produced. No billing settings were changed.
