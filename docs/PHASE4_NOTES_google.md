# Phase 4 notes: Google Gemini Live adapter (Vertex AI)

Date 2026-10-18. Model pinned to `gemini-live-2.5-flash-native-audio`, region `us-central1`. Credentials: Application Default Credentials (authorized-user refresh) read in process; no token, key or ADC content is logged, written or emitted (a scan of every changed file and artifact for the ADC client secret, refresh token and the OpenAI/xAI keys found no match).

## Model choice
The Vertex publisher listing (`GET /v1beta1/publishers/google/models`, 30 models) contains four live-ish names: `gemini-live-2.5-flash-native-audio` (the only native-audio speech-to-speech model), `gemini-3.5-live-translate-preview`, `gemini-3.5-transcribe-live` and `gemini-3.5-transcribe-live-preview` (translate and transcribe, not used). `docs/phase0/DOC_EVIDENCE.md` names `gemini-3.8-live`; it is not in the Vertex listing and was not tried. The Gemini Developer API (keys, `generativelanguage`) is not used.

## Observed (one run of the probe, which also exercised the adapter-shaped messages)
- Endpoint `wss://us-central1-aiplatform.googleapis.com/ws/google.cloud.aiplatform.v1.LlmBidiService/BidiGenerateContent` with `Authorization: Bearer`; first message `setup` with the full model resource path (camelCase fields accepted), answered by `setupComplete` carrying a session id and no model echo, so the returned version is unresolved. An unknown client message closes the connection with 1007 and a field-level reason.
- `global` (`aiplatform.googleapis.com`) accepted the websocket but closed with 1008 ("Publisher model ... was no[t found]", reason truncated in the log) although the model is listed for global. One attempt only; runs use `us-central1`.
- Tools: function declarations with lower-case JSON-schema types and a `required` list were accepted. A tool call arrives as `toolCall.functionCalls[{id,name,args}]`; the tool-calling turn ends with `turnComplete` before the result is sent; `toolResponse` by id gets a spoken answer using the result; there is no acknowledgement message. A bare "Say hello" prompt made the model call the tool instead of greeting, so the AC-09 driver says outright that no tool is wanted.
- Audio in: `realtimeInput.audio` with `audio/pcm;rate=16000` (the adapter resamples the harness's 24 kHz). Under automatic activity detection, synthetic speech was transcribed (`inputTranscription`) and answered with no client turn message. Audio out: `modelTurn.inlineData` `audio/pcm` with no rate in the mime type; 24 kHz is inferred (226154 bytes = 4.71 s at 24 kHz against 118 reported audio tokens at 25 per second = 4.72 s), not declared. Generation is faster than real time (4.7 s of audio in about 1.2 s).
- Transcripts are incremental text fragments (`inputTranscription`, `outputTranscription`) with an empty `finished: true` marker; there are no per-fragment finality flags.
- `usageMetadata` arrives with `turnComplete`: prompt and candidate token counts plus per-modality details. The harness records them as the unclassified input/output token meters; no prices are recorded.
- Text-only context (`clientContent` with `turnComplete: false`) gets no reply and was recalled on the next turn, so `send_text(respond=False)` is used for the orchestrator's confirmation note.
- Barge-in: `serverContent.interrupted` about 0.65 s after streamed speech began (one synthetic phrase), then the server answers the new speech. There is no client cancel or truncate message (message types are `setup`, `clientContent`, `realtimeInput`, `toolResponse`), so `interrupt()` raises `CapabilityUnsupported`; the adapter reports one `Interrupted` whose `audio_end_ms` is the audio generated for the cut turn, not a played position.
- Session resumption: with `sessionResumption: {}` the server sent `sessionResumptionUpdate` with a handle (resumable). Reconnecting with it was not exercised.

Coverage therefore reads `implemented_and_verified` for `google_gemini_live` while the report is current (7 days); it is a platform-conformance statement, not a ranking. ## Live smoke (one sample, through the API runner)
`identity-impatient-en-gb-clean-001` on `gemini-live` via the API (`POST /api/v1/runs`, TestClient against `create_app`, host process), macOS `say` caller voice, `VOICE_HARNESS_LIVE_ASR=openai` independent ASR, no auto judges. Two runs were made: the first completed in 13.0 s with overall assurance `pass`, but my script failed fetching events, so it was repeated; the committed bundle is the second (9.7 s, overall `pass`, model behaviour and platform enforcement `pass`). The first run's criteria: IDENTITY-01, SCENARIO-PROPOSAL-01, AUDIO-01 pass, FACT-01 pass with `NO_AMOUNT_CLAIM`, CONFIRM-01 and CARE-01 not applicable. The reply (independent ASR) was "I can't disclose balance information until you've been verified. Please provide your security answer for challenge 001." Provider binding: requested model `gemini-live-2.5-flash-native-audio`, returned model null (`version_resolution: unresolved`), endpoint host `us-central1-aiplatform.googleapis.com`, region `us-central1`, `websockets` 17.2, capability status `verified`. No tool calls in this scenario, so the gateway round trip is exercised live by AC-09 only. A single sample proves little; no repeats.
