# Phase 1 conformance audit (spec v0.3)

Audit date: 17 October 2026. Scope: `docs/voice_evals_spec_v0.3.md` against `src/`, `tests/` and `contracts/`.
Gate scope: AC-01..AC-08, AC-13..AC-18, AC-21 with the spec's Phase 1 qualifications (scripted fixtures, software playback boundary, unsigned local manifest). Physical browser/DAC playback verification is excluded (EX-01).

This audit read the code rather than the status documents, ran the suites, and fixed the gaps that were small and clearly Phase 1. Nothing was committed or pushed.

## Verdict

- **AC gate: every named acceptance check passes its executable oracle** (AC-01 Met, AC-02 Met, AC-03 Met, AC-04 Met, AC-05 Met, AC-06 Met, AC-07 Met, AC-08 Met, AC-13 Met, AC-14 Met, AC-15 Met, AC-16 Met, AC-17 Met, AC-18 Met, AC-21 Met). The suite passes on SQLite (150 tests locally, 3 live-provider skips by design) and on PostgreSQL through Compose (`make test`: 150 Python tests OK with 4 skips (3 live-provider; the golden-artifact check skips because the image does not ship `artifacts/`), 3 browser-scheduler tests OK; `make golden`, `make recovery`, `make lint` (ruff 0.17.1 + bandit) and `make audit` (pip-audit) all exit 0).
- **Full Phase 1 requirement conformance is not yet complete.** 31 requirement rows are partially met and 3 are not met; none sits inside an AC oracle, but several are MUST-level statements (details under "Open gaps").
- **Recommendation.** The AC gate can be declared met on this evidence, with the scope qualifications above, once two housekeeping conditions are satisfied by the maintainer: (1) commit this work; (2) re-run `make benchmark` so the committed baseline matches the audited source (the existing baseline predates the RFC 8785 canonicalization and decision-record changes, so timing targets stay **provisional**, as the spec requires until a matching baseline exists). Declaring "Phase 1 complete" without qualification is not supported while the open gaps remain.

## Defects found and fixed

1. **Ledger hashing was not RFC 8785.** Hashes used Python `json.dumps(sort_keys=True)`, which differs from JCS for non-ASCII text, float forms (`1100.0` vs `1100`) and UTF-16 key ordering. Added `canonical.py` (verified against RFC 8785 number vectors) and used it for event hashes, bundle verification and config/manifest digests. Consequence: hashes in bundles created before this change no longer verify; they must be regenerated. Cost measured at about 0.05 ms per event.
2. **Event `source` drifted from the closed set.** Two emitters used `adapter`. The constructor now rejects anything outside provider/orchestrator/guardrail/mcp/judge/playback and the generated schema pins the enum.
3. **Finding-scoped preservation did not exist.** Holds were run-wide only, the purge grace period was global, and the response lacked scope, availability and audit event. Implemented finding IDs, a persisted effective scope with dependency closure (causation ancestors, evidence references, sibling call/unit/request lifecycle events, the run envelope, referenced artifacts, fixture/scenario/policy identifiers), per-artifact protection and grace, a 90-day default, history, requester and access classification, and `preservation_holds` rows.
4. **Queue accounting.** Buffer overflow raised without evidence, there was no 5 s semantic-decision timeout, and limits were not recorded. Overflow and timeout now persist a typed failure event, advance the generation epoch, discard (never release) unreleased units, and limits are written into `run.started`, the run state and the manifest.
5. **Cancellation finalised while a bank outcome was unknown.** `cancel` now stays `cancel_requested` until each `outcome_unknown` call is reconciled (`reconcile_tool`) or the run is explicitly failed with unresolved-outcome evidence (`close_unresolved`); the API returns 202.
6. **Tool lifecycle gaps.** Added `assembling`/`abandoned` (partial argument streams never dispatch) and made barge-in cancel calls that have not started executing (previously `interrupt` left a requested call dispatchable).
7. **Policy decision record** carried a subset of the section 6 fields; every decision now has target, policy_id/version, reason_codes, input_hash, evidence ids and latency.
8. **Simulator branch record** had half the contract fields, no precedence/fallback, and no `simulator.utterance_generated`. Rebuilt with a closed schema, deterministic decision IDs, `reproduce()`, ledger ordering checks and a `simulator_decisions` projection. The old AC-16 test only compared two identical calls.
9. **Manifest** lacked scenario, provider/version-resolution, policy, limits, retention, deterministic/judge results, disposition, omissions and known limitations (spec section 21 requires exposing limitations).
10. **Examples** contained placeholder digests; curated examples now use real SHA-256 values and a test rejects placeholders.
11. **Scenario definitions** were hard-coded names; added a closed `ScenarioDefinition` (limits, tool sequence, fixture hash, criteria, termination map), immutable versions with 409 on conflict, and `GET/POST /api/v1/scenarios`.
12. **Findings** used a merged `IDENTITY-AUDIO-ENFORCEMENT-01`; split into the spec's `IDENTITY-01` and `AUDIO-01`. AC-02 dispositions were asserted only on the standalone golden ledger; they are now asserted on the Engine path for all three scenarios.
13. **Smaller items:** `playback.hold` state event; `alignment_source` on units; barge-in records scheduled/observed offsets and residual samples; redaction records a reason; sequence gaps persist `audio.discontinuity`; start acknowledgement declares limits; run view gains timestamps, termination reason and evidence availability; failed runs scrub buffered PCM; `GET /api/v1/metrics/{run_id}` derives hold/blocked/released/decision-latency observations with an exclusion reason for every null; scenario/hold/simulator/confirmation relational projections with unique-consumption indexes; legacy placeholder scenario rows dropped by migration 5.

## The four items the status document listed as unaudited

- **Exhaustive record metadata/examples: partially met.** Closed schemas with validated, real-digest examples now exist for tool arguments/results, the five confirmation events, simulator decision and utterance, policy decision, approval unit (`audio.output`), `transcript.revised`, hold request and record, scenario definition, run config, approval token, audio frame and the canonical envelope. Still without content schemas: most other event types (`tool.*`, `playback.*`, `session.*`, `run.*`, `artifact.*`, `preservation.*`), the manifest, findings and clock samples (IM-01).
- **Retention lifecycle: partially met.** Audio is opt-in (default off), has a seven-day TTL, is tombstoned on purge, is shielded by scoped holds and a seven-day grace, and failed runs no longer keep buffered PCM. The 30-day metadata default is only declared in the manifest: ledger rows never expire (RT-02, Not met).
- **Queue accounting: partially met.** Byte-bounded pending audio with typed overflow failure, a 5 s decision timeout, 10 concurrent sessions with 429, WebSocket heartbeat/idle, and recorded limits. Open: the default pending cap is 2 s/96,000 B rather than the proposed 30 s/8 MiB (stricter, configurable, recorded), the 100 ms client lookahead and the 2 s inbound queue are recorded but not enforced (there is no application inbound queue), and provider fallback audio is not configured (PB-20, WS-02).
- **Finding-scoped preservation dependency closure: met** for artifacts, which are the only purgeable objects (events and manifests are append-only). The closure algorithm is deterministic and tested end to end through the API (HD-06). Rubric artifacts do not exist yet, so the scope records the scenario and policy identifiers instead. Role separation and a review UI remain open (HD-02, HD-04).

## Open gaps and proposed fixes

Not met:

- **RT-02 metadata retention (30 days).** Proposal: a purge job that replaces event payloads older than the retention class with a tombstone that retains `event_hash`, `prev_hash` and sequence so the chain still verifies, honours holds, and records the tombstone in the manifest.
- **FN-03 operator UI.** Not a gate item. Proposal: a minimal run-detail page backed by the existing events/metrics/holds endpoints.
- **SE-04 resampler (resolved 2026-10-17).** `resample.py` now uses libsoxr (C-backed); the Nova adapter uses a stateful `StreamResampler`. CPU-heavy work still runs on the event loop at current (sub-millisecond per 10 s of audio) cost; revisit under Phase 5 load tests.

Partially met, ordered by risk:

1. **TL-02 per-call `cancel_requested`/executing.** Execution is one transaction, so an in-flight call is never observable. If live adapters need mid-execution cancel, split dispatch from commit with an outbox state per call.
2. **LT-02 runtime clock sync.** Wire the eight-sample exchange (connect and every 30 s) over the WebSocket and persist `clock_sync_samples`; until then browser-side latency is unavailable by design.
3. **HD-02/SE-01 roles.** Introduce operator and reviewer tokens with per-route authorization; enforce TLS when `HARNESS_BIND` is non-loopback.
4. **DM-01 relational shape.** Promote run/session/event identifiers from JSON payloads to indexed columns and add the missing unique experiment key and indexes.
5. **OB-01 telemetry.** Add OTel metrics and logs, span links for asynchronous jobs, and per-turn/guardrail spans.
6. **OB-04 export.** Add an NDJSON/schema-bundled export and a separate restricted reviewer export.
7. **PB-22/AR-02 guardrail layers.** Content layer (prohibited disclosure, advice, injection, secrets) and redact/replace/escalate actions.
8. **MC-06 error shape.** Return `retryable` and a safe `message` and constrain codes to the catalogue.
9. **AR-06 gateway rate limiting; EN-06 `history_diverged`; PB-16 provider-vs-ASR revision sources; PB-17 client token ordering; SC-03 stop conditions/max turns; WS-02 inbound queue; SE-03 graceful shutdown steps; AP-02 run states; AP-04 metric summary; AP-07 download links; FN-02 explicit causation/unknown on every event; IM-01 remaining schemas; HD-04 review UI.**

## Residual risks

- **Hashes changed.** Any exported bundle created before this audit fails verification under RFC 8785. `artifacts/golden-run.json` was regenerated (and is now checked by a test); external copies must be regenerated.
- **Benchmark baseline is stale.** `artifacts/phase1-final-baseline.json` records an older source hash, and it was measured in a container limited to 1 GiB of memory against a spec reference host of at least 16 GiB. Timing targets remain provisional.
- **Scripted semantics.** Audio is PCM silence with scripted transcripts. Tests prove enforcement mechanics, not ASR, audibility or judge quality; no AC result should be reported as live semantic success.
- **Custom scenarios are inert.** `POST /scenarios` stores immutable definitions but only the three built-ins run (`runnable: false`). The check-then-insert in the handler is not atomic across concurrent writers (a losing writer's insert is ignored while reporting `created: true`).
- **Approval token IDs are in the ledger and exports.** They are single-use, expire in 30 s and are signed, but they are bearer identifiers.
- **SQLite fallback** has no append-only trigger; tamper evidence relies on hash verification there. Production default is PostgreSQL.
- **Scheduler lookahead** (100 ms) and token ordering are not enforced in the browser client.
- **Hold race test is order-agnostic by nature.** It asserts the two legal outcomes exactly but cannot force one; the deterministic hold-first and purge-first cases are covered separately.

## Exclusions (documented, not failures)

- **EX-01 Physical browser/DAC playback.** Audibility, device latency and loopback measurement were not performed because the operator cannot. All playback evidence is the software boundary (`playback.ack`, `physical_audibility: unknown`). Node scheduler tests and Python WebSocket clients are not evidence of audibility.
- **Live providers, live ASR/judge calibration, signing, cost accounting** are later-phase scope and are listed as Out of Phase 1 scope in the table.
